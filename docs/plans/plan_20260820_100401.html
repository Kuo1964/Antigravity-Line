🛡️ 階段一：Codebase Reconnaissance (程式碼偵查)

🚨 21:30 發送失敗根本原因

從 Log 中發現，今晚的失敗原因與昨天早上「貼上假圖片」的起因是同一個源頭：網路圖片下載模組 (`image_crawler.py`) 的防護過於脆弱！

1. 爬蟲找到了台塑企業的早安圖網址 (`https://sticker.fpg.com.tw/...`)。

2. 爬蟲嘗試下載時，發生了 `Read timed out` (連線超時)。

3. 致命錯誤：程式在抓到例外錯誤時，沒有自動切換去抓備用的 Unsplash 圖片，反而直接把這串「網址文字」當成檔案路徑回傳給了下一步！

4. 負責將圖片塞進剪貼簿的程式發現「這串網址」在電腦硬碟裡根本找不到，於是直接報錯 `[ERROR] 圖片檔案不存在`，任務直接宣告中斷失敗。

📌 受影響半徑 (Impact Surface)

  • `app/services/image_crawler.py` (圖片下載與防護機制)
  • `app/services/line_desktop_controller.py` (鍵盤操作與焦點)
  • `app/services/macos_ui_adapter.py` (底層按鍵與剪貼簿操作)

🔒 不可更動的核心/受保護模組

  • `login_line_only.py` 等其他獨立排程腳本。
  • `monitor_log_analyzer.py` 監控排程。

🛡️ 階段二：Brownfield Change-Spec (變更規格化)

為了徹底根絕這幾天連續發生的：假圖報錯、超時未備援、中文輸入法吃字、座標偏移失焦等所有相關問題，我規劃了以下最小變更 (Minimal Intervention) 與驗證標準：

1. 圖片爬蟲防護 (Image Crawler Guardrail)

  • 變更要求：嚴格檢查 `resp.status_code` 與 `Content-Type` 是否為 `image/*`，且檔案大小必須 > 1KB。
  • 例外處理：無論是「超時 (Timeout)」、「被擋 (403)」、「下載到文字檔」，一律自動熔斷並切換至 Unsplash 備用圖片，確保 100% 必定能回傳一張真實的圖片路徑。

2. 全鍵盤無失焦操作 (Keyboard-Only Navigation)

  • 變更要求：移除危險的 `win_h - 60` 絕對座標點擊。
  • 行為約束：透過 `Cmd + 2` 切換聊天室列表，透過 `Cmd + F` 定位搜尋框。利用 LINE 點擊聯絡人後「自動對焦輸入框」的特性，直接進行後續操作，無視任何視窗陰影與尺寸變化。

3. 百分百無損中文輸入 (Clipboard Paste)

  • 變更要求：全面淘汰 `appscript` 的 `keystroke` 打字模擬。
  • 行為約束：不論是搜尋名字（如郭泊彤）還是發送文字，一律使用 `pbcopy` 寫入剪貼簿後發送 `Cmd + V`。
