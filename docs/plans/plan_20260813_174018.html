服務無法正常啟動之絕對路徑與 Daemon 修復計畫 (Implementation Plan)

🔍 診斷原因 (Root Cause Analysis)

檢視 ngrok.log 與 uvicorn.log，徹底揭露為何服務先前跑得好好的，現在卻永遠無法啟動：

1. `ngrok: command not found` (環境變數 PATH 缺失)：

  • 經檢查，`ngrok` 的實際安裝路徑為 Homebrew 目錄 `/opt/homebrew/bin/ngrok`。
  • 當從代理工具、自動化腳本或非互動式 Shell 啟動 `start.sh` 時，環境變數 `PATH` 缺乏 `/opt/homebrew/bin`，導致系統拋出 `ngrok: command not found`，隧道完全無法啟動。

2. Uvicorn 在非互動 Shell 中接收 SIGHUP/SIGTERM 關閉：

  • `uvicorn.log` 顯示 `Started server process [8144]` 後瞬間觸發 `Shutting down`。
  • 原因為腳本未加入系統層級獨立 session 解耦 (`nohup` + 絕對路徑 + `disown`)。

---

🛠️ 擬定修復方案 (Proposed Changes)

1. 全面改用絕對路徑 ([start.sh](file:///Users/johnkuo/Library/CloudStorage/GoogleDrive-johnyhkuo@gmail.com/我的雲端硬碟/worktemp/Antigravity-Line/start.sh))

  • 在 `start.sh` 與啟動腳本中，明確宣告 `NGROK_BIN="/opt/homebrew/bin/ngrok"` 與 `PYTHON_BIN="$PROJECT_DIR/venv/bin/python"`，徹底解決 `command not found` 遺憾。

2. 獨立 Session 常駐監控

  • 以 `(nohup "$NGROK_BIN" http 8000 > ngrok.log 2>&1 &)` 啟動，並加載自動健康驗證。
