Antigravity 代理在專案中的 5 大核心短板

以下為 Agent 自身在過去 16 個 Session 中暴露的最具破壞力、也是最浪費使用者時間的行為盲點：

短板 1 「被動依賴人類手機測試」而非「主動沙盒 Mock E2E 驗證」

最耗時元凶

盲點現象： Agent 寫好代碼後常直接宣稱「已修復完成，請您在 LINE 上發送訊息測試」。當使用者拿起手機發送後發現完全沒反應（卡住或 ngrok 斷線），使用者被迫回報「我發送了但沒動作」，浪費大量來回。
根本原因： Agent 把「單元測試綠燈」等同於「全鏈路正常」，沒有在交卷前自主執行 curl -X POST /callback -d '{"events":[...]}' 來檢驗真實的 LINE 回應與輸出。

短板 2 運行態環境感知遲鈍 (Runtime Context Blindness)

Session 12 核心痛點

盲點現象： 在執行 ./start.sh 或重啟 FastAPI 前，Agent 未主動檢查舊的進程是否殘留或端口 8000 是否被佔用，導致服務看似跑起來但實際處於崩潰或衝突狀態。
根本原因： 缺乏 Pre-flight (前置環境檢查) 與 Post-flight (後置存活確認) 意識，習慣盲目執行啟動腳本。

短板 3 Subagent 派工時的「契約割裂與整合驗收缺失」

Tickets 開發階段

盲點現象： 主 Agent 啟動 Subagent 平行執行 TICKET-001 與 TICKET-003，Subagent 在隔離環境跑完各自的 unit test 綠燈回報。但主 Agent 在合併代碼後，沒有立刻跑整合測試 (Integration Test)，直接交卷給使用者，導致上線即破裂。
根本原因： 缺乏「主代理驗收責任制 (Master Agent Acceptance Contract)」。

短板 4 微步確認造成的「分析癱瘓 (Analysis Paralysis)」

100 輪對話膨脹

盲點現象： Agent 常為了極小的非破壞性操作（例如讀取一個日誌或列出目錄）停下來輸出長篇 plan 等待使用者核准，過度消耗了使用者的專注力。
根本原因： Agent 未能區分「破壞性操作（需人類授權）」與「探索/沙盒測試（應果斷自主推進）」。

短板 5 跨 Session 記憶衰退 (Memory Decay)

跨天對話遺忘

盲點現象： 每次換一個新的 Session，Agent 常需要使用者重新提醒「不能動到早安圖」、「Google Drive 掛載有延遲」等專案硬性約束。
根本原因： 缺乏常駐的專案記憶機制（如 AGENT_MEMORY.md 或嚴格的本地 Rule），導致知識隨 Session 結束而丟失。

AI 代理四大實踐改造方案 (Architecture Upgrades)

針對上述 5 大短板，以下是具體落地的工程化改造方案，徹底解放使用者的人力：

方案一：主動式 E2E Mock Webhook 驗證腳本

徹底告別「人類手機盲測」

在 tests/mock_line_webhook.py 建立模擬發送腳本。Agent 在修改完任何 LINE 相關程式碼後，強制自動發送連續兩輪測試 Payload（包含單行指令、多專案切換、超過 2000 字訊息），確認 FastAPI 回應 200 OK 且輸出符合預期後才回報使用者。

$ python -m tests.mock_line_webhook --simulate-multi-turn

方案二：前置/後置運行態守護 (Pre/Post-Flight Hooks)

消除端口佔用與死循環

Agent 在調用 run_command 啟動服務前，自動觸發「清理守護」：
1. 檢查 8000 端口佔用 ➜ 自動終止舊進程。
2. 啟動後輪詢 http://127.0.0.1:8000/docs 驗證服務存活。
3. 檢查 ngrok API 確保 Public URL 已更新。

$ ./doctor.sh --fix-stale-ports

方案三：Subagent 派工契約與主代理整合驗收制

杜絕整合即崩潰

派發 Ticket 給 Subagent 時，強制要求附帶「介面契約 (Interface Contract)」，Subagent 完成後主 Agent 必須在 Workspace 自動執行 pytest tests/test_integration.py，確保雙軌切換與 Markdown 轉譯在整合成品中無縫協同。

方案四：專案長期記憶庫 (AGENT_MEMORY.md)

跨 Session 經驗零衰退

建立 AGENT_MEMORY.md，記錄專案所有的「踩坑禁區 (Forbidden Zones)」與「已驗證的最佳架構決策 (Known Decisions)」。任何新開啟的 Session，Agent 啟動時自動載入此記憶庫，絕不重蹈覆轍。

Template 01 主動式 Mock LINE Webhook 測試器 (`tests/mock_webhook.py`)

可用於 Agent 自動自檢 
# tests/mock_webhook.py
import urllib.request
import json

def simulate_line_message(user_id="U_TEST_USER", text="你好，請幫我列出專案"):
    url = "http://127.0.0.1:8000/callback"
    payload = {
        "events": [{
            "type": "message",
            "replyToken": "mock_reply_token",
            "source": {"userId": user_id, "type": "user"},
            "message": {"id": "10001", "type": "text", "text": text}
        }]
    }
    req = urllib.request.Request(
        url,
        data=json.dumps(payload).encode("utf-8"),
        headers={"Content-Type": "application/json", "X-Line-Signature": "MOCK_SIG"}
    )
    try:
        with urllib.request.urlopen(req, timeout=3.0) as resp:
            print(f"[✓ Mock Webhook] 發送成功: {text} -> HTTP {resp.status}")
            return True
    except Exception as e:
        print(f"[✗ Mock Webhook] 發送失敗: {e}")
        return False

if __name__ == "__main__":
    simulate_line_message(text="查詢目前專案狀態")
    simulate_line_message(text="切換至專案 Antigravity-Line")

# AGENT_MEMORY.md (專案禁區與硬性決策)

## 🛑 禁區清單 (Forbidden Zones - 嚴禁擅自修改)
1. **早安圖派發模組**：獨立於主控制流程，嚴禁修改其排程與圖片生成邏輯。
2. **Google Drive 路徑硬編碼**：工作目錄依賴 CloudStorage，嚴禁寫入非專案內的本機暫存路徑。

## 💡 已驗證的最佳決策 (Validated Architecture Decisions)
1. **雙軌專案切換**：`AgentSessionEngine` 必須同時支援「狀態鎖定」與「語意判斷」。
2. **LINE 字數分段**：單則超過 2000 字元必須調用 `format_markdown_for_line` 自動分段發送。
3. **開關機時序**：關機前 5 分鐘優雅釋放端口；開機後守護進程等待磁碟掛載最長 10 分鐘。
